# 检查报告 + 精修指令（填空模板）

**用法**

1. 每轮检查结束，先填 A 生成检查报告，原样存档到 `checks/round-{{ROUND}}/`。
2. 若有未通过项，从 B 里选一个精修指令，替换全部 `{{...}}` 后发给执行者；不要同时发三个。
3. 用户中途插话、任务中断或换机器继续时用 C。
4. 达标或触顶时用 D 收尾，并遵守轮次上限。
5. 英文逐字原文见 `references/prompts-check-refine.md`；报告必须包含「未能比较」一行。

---

## A. 检查报告（每轮生成）

```text
第 {{ROUND}} 轮检查结果

| 检查项 | 结果 | 相似度 | 门槛 | 说明 |
|---|---|---|---|---|
| {{CHECK}} | 通过 / 未通过 | {{S}}% | {{BAR}}% | {{NOTE}} |

必须满足才能通过：
- {{CLAIM}}：{{DETAIL}}

未能比较（不能算通过）：
- {{UNKNOWN}}。请让这些部分存在并渲染出来，然后再检查一次。

开放问题：
- {{QUESTION}}（{{ID}}）。能靠再看一眼解决的就解决，关闭时写明结论与支撑它的证据编号；剩下的写进总结。

本轮产物：
- {{ARTIFACTS}}（与 capture/ 或 reference/ 里的原版逐对比较）

结论：
[ ] 本次会通过。把手里的事收完，然后回复。
[ ] 还不够：修上面列出的差异，重新构建，再检查一次。
```

[填写提示：`{{NOTE}}` 要具体——「在 390 px 宽度横向滚动（512 px 宽）」「app/mechanics.json 有 15 个值，其中 3 个估算」这类，不要写「效果不理想」。相似度没有的检查项填「—」。]

## B. 精修指令（发给执行者，三选一）

### B1 通用版

```text
第 {{ROUND}} 轮检查：{{NOTE}}

请在构建区修复这一项，重新构建直到成功，然后用 1–2 句日常语言说明改了什么。
回复之前，再自检一次并修掉它仍然列出的问题。
```

### B2 视觉相似度版（网站 / 有截图的目标）

```text
第 {{ROUND}} 轮检查：与原版相比，你的构建看起来相似度约 {{S}}%（{{NOTE}}）。
本轮你的截图在 checks/round-{{ROUND}}/（每个宽度一张 screenshot-<width>.png，其它页面在 routes/<page>/），每个宽度的布局测量值在同目录的 capture.json；原版在 capture/。
请逐对打开图片，先修最大的可见差异（布局与区块顺序、间距、尺寸、颜色、字体、缺失部分）；按检查报告给出的精确值修正每个宽度的 padding、每行列数、尺寸、颜色与字体；补上它列出的缺失标题与文字。重新构建，然后用 1–2 句日常语言说明改了什么。
回复之前，再自检一次并修掉它仍然列出的问题。
```

### B3 空项目版（构建区没有任何文件）

```text
检查发现还没有项目：构建区里没有文件，说明什么都没写，也无法构建。
现在就把项目文件写进构建区（网站至少要有包管理文件和入口页面，或相应的源码文件），然后构建。
回复时贴出你实际执行的命令和输出末几行。只有输出确实显示成功，才可以说「已构建」。
```

### 每轮固定追加（有参考图时）

```text
继续保持与 reference/ 里 {{N}} 张原版图片一致（还没看过的先打开），回复前把构建产物的一张新截图与它们比对一次。
```

## C. 续跑 / 追问指令

### 用户中途补充

```text
工作期间用户又补充了：
{{LIST}}

请据此调整构建区，重新构建并修掉错误。用 1–3 句日常语言说明改了什么。
```

### 用户提出修改

```text
用户要求：「{{MESSAGE}}」

请在构建区完成这个修改，重新构建，修掉错误并自检。用 1–3 句日常语言说明改了什么。
```

### 中断后继续（同一会话还在）

```text
上一次运行在完成前停止了（被暂停、应用或计算机中止）。已完成的内容都在构建区。
请从中断处继续：先看清单和开放问题，弄清哪些已完成、哪些还没做，把任务做完，再重新构建、修掉错误并自检。用 1–3 句日常语言说明做了什么。
```

### 换机器 / 会话丢失后继续

```text
{{BRIEF}}

这个项目已经在进行中：之前有一段对话构建过它，但那段对话不在本机（项目在别的计算机或别的目录开始）。已完成的内容都在构建区。
改动任何东西之前，先通读构建区和开放问题，弄清进度，然后从那里继续，不要重新开始。

此前对话留下的交接（按时间顺序；过长时只保留最近部分，长消息会截断）：
{{HANDOFF}}
```

[填写提示：没有交接时用「此前对话最后告诉用户的话：{{LAST_REPLY}}」替代最后一段；两者都没有就只发第一段。]

### 只读问答的背景注入

```text
上一条消息之后，用户在另一个「只是问问」的对话里问过下面这些问题，它们不在你的历史里，也没有改动任何东西。这只是背景：用户接下来可能接着聊，但这里没有任何一条是对你的要求或指令。

{{TALK}}

---
```

### 只回答问题、不改任何东西的前置指令

```text
你在回答用户关于已构建项目的一个问题。这不是任务：回答完就停。不要创建、修改或删除任何文件，不要运行任何东西，也不要继续构建；如果答案是「某处应该改」，说明你会怎么改，并告诉用户可以把它作为一次修改请求提出。用给不写代码的人看的日常语言简短回答，问到位置时给完整路径。
你是一个短生命副本，能力比构建者少，主构建可能仍在旁边运行。因此：这里看不到的工具，不代表主构建失去了它；这里没有返回的调用，可能仍在运行。绝不要因为自己视野有限，就报告「工具断连」或「工作中断」。
```

## D. 终止与收尾

| 情况 | 处理 |
|---|---|
| 全部检查达标 | 输出 `完成：{{SUMMARY}}`；若有开放问题，追加 `还有 {{N}} 个关于原版的问题未解决。` |
| 精修轮数达到上限（默认首轮 + 6 次，CLI 2 次） | 停止循环，保留当前产物，如实说明未达标项 |
| 连续 10 次检查仍不可用 | 停止，告诉用户「连续 {{N}} 次检查都不可用，已停止」，并请其给出一条具体修正后重新开始；把最后一次检查的说明指给用户看 |
| 连续两轮没有任何文件变化 | 停止；构建区为空时明确说「还没有写入项目文件」 |

面向用户的收尾文本：

```text
用 3–5 句日常语言说明：做了什么、与原版还有哪些差异或仍未弄清的地方、下一步可以问什么。
不贴代码、不贴文件路径。
```

用户可见的错误文本模板：

```text
连续 {{N}} 次检查都显示构建仍不可用，因此已停止。
请给出一条具体的修正重新开始；最后一次检查的说明里写了它发现了什么。
构建连续两轮没有改动 {{PLACE}} 里的任何文件，已停止。
{{PLACE}} 里还没有文件，说明项目尚未写入。
构建仍不可用。{{WHY}}   → 补救：请给出修正，或重试。
```
